# ParisComedy — Homepage Featured Widget Audit (2026-05-24)

## Status: GREEN ✅

## Root cause
`renderFeatured()` in `index.html` silently emptied the featured grid when the API returned `[]`, but the surrounding markup (section subtitle and CTA) kept claiming "verified, highlighted comedy nights in Paris" exist. The widget had no stale static fallback cards — the bug was honest empty state for the cards, dishonest static copy around them.

Additional stale-copy bugs alongside:
- Hardcoded "May 19–25" subtitle on Coming Up This Week.
- "every show in Paris" overclaim in newsletter footer.
- "May 19 – June 8, 2026" internal JS comment.

## Did the widget use stale fallback?
**No.** The grid is purely API-driven. The lie was in static surrounding copy, not stale data.

## What happens now when `/api/listings?featured=1` is empty
- Grid: empty (no cards).
- Subtitle: "No featured shows right now."
- CTA: "Featured spots are open — claim one →" (links to `/pricing.html#featured-promo`).
- No "Verified, highlighted comedy nights in Paris" claim.
- No "These shows are Featured" CTA.

## What happens when `/api/listings?featured=1` is non-empty
- Grid: up to 3 cards, rendered via the same public serializer used by `/api/listings`.
- Subtitle: "Editorial picks and paid Featured Show Promos."
- CTA: "Want your show featured? See pricing →".

## Guardrails added
- `check_homepage_truthfulness()` in `scripts/guardrails/check_invariants.py`:
  - 11 always-forbidden strings (stale launch banners, dates, overclaims, PII, canceled shows, internal provenance).
  - 2 conditionally-forbidden strings ("Verified, highlighted comedy nights in Paris", "These shows are Featured") — fail only when the featured API is empty.
